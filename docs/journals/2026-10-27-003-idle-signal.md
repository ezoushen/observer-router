# 2026-10-27-003 — the idle gate reads any server's metrics

## 02:20 — `idle_signal` and an `ac_only` warning

- Request: after listing what detects a busy or idle lane, "machine idle" (input, load or screen
  lock) was dropped, and the two remaining mismatches were to be closed: the idle gate understood
  only Splash's counter names, and `ac_only` reads the router's battery even for a lane on
  another host.
- Outcome: `idle_signal` names the metrics, either counters (`submitted`, `finished`) or gauges
  (`in_flight`). Gauges are matched by name with labels stripped and summed, since a server such
  as vLLM reports one per model. A gauge lane has no submitted count, so only in-flight work
  counts as activity, which the grace period covers. A missing named metric makes the lane
  unreadable, which ages into idle as before. Unset, the Splash names apply, so the live setup
  is unchanged. Two providers watching one URL with different signals are rejected, because the
  sampler reads each URL once.
- Outcome: start-up warns when `ac_only` is set on a provider whose `url` is not loopback. A
  refusal was considered and rejected: a lane on this machine can legitimately be addressed by
  its LAN address.
- Not done: nothing live uses it. The one remote lane, `mbp14`, exposes no `/metrics` (404), so
  its idle state cannot be read; `ac_only` and `idle_metrics` stay off for it.
- References: `IdleSignalTests`.

## 02:40 — Review: the new parser was stricter than the old one

- Outcome: an independent review compared the new parser with the old one on a range of bodies.
  They agreed on everything except three things the change had made worse, now fixed: a trailing
  or doubled space made a Splash body unreadable (the gate would have silently stopped gating),
  NaN or infinity raised instead of reading as unreadable, and a metric listed twice in
  `finished` was counted twice, so it is now a config error. Intended differences remain: a
  labelled line parses, and an unlabelled name that appears twice is summed, where the old
  parser kept the last.
- Not changed: a fractional gauge is truncated (0.5 + 0.4 reads as 0), which does not matter for
  gauges that count requests.
